# Add a brand to a Chassis token and asset repository

A brand of the Chassis design system lives in two repositories, both written by the `init` command of their builder and both synced by name: a repository of tokens, Tokens Studio files in `source/` that `@chassis-ui/tokens` builds into SCSS, Swift and Android resources, and a repository of assets, fonts and images in `source/<brand>/` that `@chassis-ui/assets` copies into the names of the web, iOS and Android. A site or an app builds with the brand of the same name in both. This skill adds one brand to both, tokens first, since the fonts of the brand are placed by the families and the weights its tokens name.

The skill edits files and runs the commands of the two packages. It needs no Figma tool and no server tool other than `chassis_get_reference` for its references: the one step it cannot do, the export of the new brand to Figma with Tokens Studio, is the designer's, and the skill ends by saying what that step needs. One check of the output, that the stylesheets load their fonts, needs a browser; without one, the summary names it as not done.

## What to settle first

Collect what is missing before the first edit; the brand is only as good as these inputs, and none is guessed:

| Input                   | What it is                                                                                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The name                | Lowercase letters, digits and single hyphens, a letter first: `acme`, `north-wind`. One name in both repositories; it becomes a folder, an option, a mode and a part of every file a release writes                                                                       |
| The repositories        | The folder of each, with a `chassis` block in its `package.json`. Either may be absent from the task: then only the other half is done, and the summary says so                                                                                                           |
| The palette             | One light color per palette role that the brand changes: `primary`, `secondary`, `neutral`, `danger`, `success`, `warning`, `info`. The rest keeps the value of `base/brand-base`                                                                                         |
| The families            | The family of each role, `ui`, `prose`, `display`, `code`, or the role whose family it uses, and for every role the weights `elegant`, `normal`, `strong`, `mass` by style name as the font spells it; or the word that the brand keeps the families of `base/brand-base` |
| The font files          | A download of each family, outside `source/`, with its license. Nothing is fetched from the web without the user                                                                                                                                                          |
| The radius              | Whether the brand changes the radius scale or the radius of a component; most do not                                                                                                                                                                                      |
| The images and the icon | The logos, the favicons, the social image and the app icon bundles the designer exported for the brand, or the word that they come later                                                                                                                                  |
| The apps                | Which apps of `chassis.build` the brand builds for; by default all of them                                                                                                                                                                                                |

## How much of each reference to read

The three references are the procedures, one per kind of file, and each is read whole at the step that uses it, since every step of it is taken: [tokens.md](./references/tokens.md) before the first edit of the repository of tokens, [fonts.md](./references/fonts.md) before the first font is copied, and [images.md](./references/images.md) before the first image or bundle is placed. A section of one is fetched by itself only when a later step sends back to it: a link with an anchor (`#…`) names the section, and `chassis_get_reference` with that `section` returns it with the introduction of its file. When several sections of one file are needed at a step, `sections` takes them together and returns them under one introduction.

## The twelve rules

1. **Edit `source/`, never `dist/`.** In a repository of tokens `dist/` and `Package.swift` are committed and written by `build` and `swift-package`, and go into the commit with the change to `source/`; in a repository of assets `dist/` is not committed at all. A file of `dist/` is never written or fixed by hand.
2. **`$themes.json` and `$metadata.json` are Tokens Studio's.** The plugin writes them at every sync, so an edit is the smallest one: a new option inserted after the last option of the `brand` group and a new set name in `tokenSetOrder`, with every other option, every `$figmaVariableReferences` and every `$figmaStyleReferences` left byte for byte as they are. A new option has no `$figma*` fields until the designer exports it ([tokens.md](./references/tokens.md#the-option-of-the-brand)).
3. **A brand set declares what the brand changes, with the names of `base/brand-base`.** The `base` of each palette color it changes, the font families and weights, the radius where it differs; nothing else. The committed sets of `chassis-ui/website-tokens` declare more than that, restating base values such as the whole radius scale and the context weights: follow the rule, not that example, and declare a group a committed set declares only where the brand changes it. A token the set does not declare keeps its base value, and a token named otherwise than in `base/brand-base` is a new token, which the lint and the build do not refuse but which no theme or app references ([tokens.md](./references/tokens.md#the-token-set-of-the-brand)).
4. **A font weight is the style name the font spells.** `SemiBold` or `Semi Bold`, as the family's own files name it, so that Figma finds the style; the build reads either as 600. The first family of a font family token is the name the stylesheet declares, letter for letter.
5. **The new brand sets the next visibility switch.** `figma.switch.brand.mode-<n>` is `true` in exactly one option of the group: the set of the brand sets the first switch that no set selected by an option of the group sets to `"true"`, the sets of `base/` included (`base/brand-default` sets `mode-1` in `chassis-ui/website-tokens`), and a switch `base/brand-base` does not have is added there as `"false"` first. In a repository fresh from `init`, `base/brand-base` has one switch per brand, so the new brand always adds the next one ([tokens.md](./references/tokens.md#the-visibility-switch)).
6. **A brand holds every font it ships, and `source/_default/` holds none.** A font of `_default` would reach every brand without a file of its name, and a brand that replaces half of a role would ship two families. The files by weight and the licenses go in `source/<brand>/_shared/fonts/`, the variable files and the stylesheet of the web app in `source/<brand>/<web app>/fonts/`, the stylesheet of the native app in `source/<brand>/<native app>/fonts/` ([fonts.md](./references/fonts.md#what-a-brand-holds)).
7. **Same names, same extensions, in every brand.** A file is `<role>-<weight>.<ext>`, `-italic` after the weight, `<role>.<ext>` for a variable font, the app fonts `.ttf` in every brand, so a page or an app that names `ui-strong.woff2` or `ui_strong.ttf` gets the font of the brand it was built for with no change to its code. The folders of the new brand are compared with those of a committed brand before the build ([fonts.md](./references/fonts.md#compare-with-another-brand)).
8. **The stylesheet and the license go with the family.** Every brand has its own `fonts.css` per app that declares every family of the brand once, under the name its tokens give, and a `<role>-license.txt` beside the files of each family. A role set in the family of another role has no files for the web and copies for the apps.
9. **A reserved font name is not instanced.** When the first line of the license reserves the name of the family, the files by weight come from the download and `chassis-assets static-font` is not run on it: a file it writes is a modified version, which may not carry the name ([fonts.md](./references/fonts.md#get-the-files-and-check-the-license)).
10. **Fonts and raster images are Git LFS files.** `git check-attr filter <file>` answers `filter: lfs` for a new `.ttf`, `.woff2`, `.png`, `.jpg` and `.webp`, the extensions of the `.gitattributes` of the repository; `.ico`, `.svg`, `.css`, `.json` and `.txt` are plain files, as in the committed brands. A font or a raster image that answers otherwise is not committed, and a pointer file is never read as the font or the image it stands for.
11. **The source lint is passed by fixing the file.** No entry in `lint.allow` of `chassis.checks.json`, no renamed rule, no set removed from an option to get past a message: the lint names the set and the token, or the file and the rule, and that is what changes.
12. **Nothing is committed, pushed or released unless asked.** Both repositories release on a push to `main` with a new version, and the version and its changelog entry are the maintainer's step. The skill leaves the files changed, the checks run, and the changelog entry drafted in the summary, not written.

## Workflow

The steps run in this order; a step whose repository is not in the task is skipped and named in the summary.

1. **Tokens.** Read [tokens.md](./references/tokens.md) whole, then tell the layout of the repository by its `source/` ([the two layouts](./references/tokens.md#the-two-layouts)) and read `base/brand-base` for the names of the brand tokens; a committed brand set fresh from `init` declares its switch only and shows none of them. Write `source/brand-<brand>/brand-base.json` from the palette, the families, the weights and the radius; add the set to `tokenSetOrder` of `$metadata.json` after the last set of the other brands; insert the option after the last option of the `brand` group of `$themes.json`; add the name to `chassis.build.brands` of `package.json`. Then, from the root of the repository, `npx chassis-tokens lint-source`, `npx chassis-tokens build`, `npx chassis-tokens diff`, `npx chassis-tokens swift-package` and `npx chassis-tokens verify`, and read what each reports before the next: the lint names a set and a token, the diff lists the files of the new brand as added and must list nothing removed or changed in the other brands. The build also writes the timestamp line of every committed file of `dist/` again, so `git status` shows the files of the other brands as modified: they go into the commit, and `verify` ignores that line.
2. **Fonts.** Read [fonts.md](./references/fonts.md) whole. For each role that has a family of its own in the tokens: the license, the files by role, the files by weight with `chassis-assets static-font` or from the download, the `.woff2` beside each `.ttf`, the block of the stylesheet of the web app, then the stylesheet of the native app and the copies of a role set in another family. Compare the three font folders with those of a committed brand before the first build.
3. **Images and app icon.** Read [images.md](./references/images.md) whole. Place the logos in `_shared/images/`, the favicons, the social image and the web manifest in the folder of the web app, and the `.icon` and `.adaptive` bundles in the folder of the native app, each under the name the other brands use. Add the brand to `chassis.build.brands` of `package.json`, to `axes` of `chassis.subset` when a variable font has an optical size axis, and its jobs to `contracts` of `chassis.checks.json`, copied from the entries of a committed brand, less an entry whose reader is a consumer that will not build with the new brand. Check the web manifest and the app icon bundles against the brand before placing them: a name, a color or a layer file of another brand in an export is reported, not fixed.
4. **Build and check.** In the repository of assets, `npx chassis-assets lint-source`, then the build of a release, `pnpm build:release` where `package.json` has the script and `npx chassis-assets build` otherwise, then `npx chassis-assets verify`: after a plain build, `verify` skips the contracts of the `res/` folder and the asset catalogs, which only the release build writes. Then the output of the brand against that of a committed brand ([fonts.md](./references/fonts.md#build-and-check), [images.md](./references/images.md#build-and-check)). Then `git check-attr` on every new binary (rule 10), and `git status` to see that nothing under `dist/` of the repository of assets, and nothing under `node_modules/` or a download, is about to be committed.
5. **Hand over.** The summary names what the designer and the maintainer do next: the export of the token sets to Figma with Tokens Studio and the publishing of the library, which gives the option its Figma references ([tokens.md](./references/tokens.md#the-export-to-figma)); the version and the changelog entry of each repository, with the files the release adds, drafted from the diff; and the site or the app that builds with the brand, which takes it by the same name in both.

## Deliverable format

| Bucket       | Meaning                                                                                                                                  |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **Tokens**   | The files of the repository of tokens written or changed, and what `lint-source`, `build`, `diff`, `swift-package` and `verify` reported |
| **Fonts**    | The roles with files of their own, the family and the weights of each, how the files by weight were made, and the roles in another       |
| **Images**   | The images and the bundles placed, by app, and the contracts added                                                                       |
| **Checks**   | Every command run, with its result; a failing one with its message                                                                       |
| **Hand-off** | The Figma export, the changelog entries drafted, the version step, the consumers of the brand                                            |
| **Left out** | A step skipped because its repository, its files or an input was not in the task, each with what it waits for                            |
| **Blocked**  | What could not be done, with the exact failure                                                                                           |

Name at the top which repositories were in the task, and the name of the brand as it is written in both.
